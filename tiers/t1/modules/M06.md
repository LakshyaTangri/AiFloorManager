# M06 — Outbound reachability and the commissioning firewall sheet

**Module:** M06 network connectivity · **Subsystem:** S02 · **Controls:** C1, C13
**Depends:** M01 (host qualified), SPEC §15 · **Blocks:** M12, M13, F04 enrolment
**Class:** Platform (brief + code review; on-site test required)

## The link has one direction

SPEC §15 makes the link device-initiated and outbound only, with no inbound firewall rule ever. The
assessment therefore treats an offered inbound rule as a finding — `inbound_rule_offered` — rather
than as helpfulness from the customer's IT. Accepting it would enlarge the customer's attack surface
to buy nothing: the device already dials out.

## An inspected TLS session is worse than no session

A TLS-inspecting proxy terminates the session and presents its own chain. The device pins the Tangri
Service CA for these endpoints and does not trust public roots, so a customer root shows up as
`tls_intercepted` and the posture becomes `REFUSED`, not `degraded`. The remedy is a passthrough
allowlist on the proxy. Installing the customer CA would make the pin meaningless, so it is not an
option the code can express.

`alpn_stripped` is the same failure seen from the other side: MQTT over 443 needs ALPN
`x-amzn-mqtt-ca`, and a proxy that removes it has read the connection.

## Unreachable is not broken

| Posture | Meaning |
|---|---|
| `online` | every endpoint reachable and unmodified |
| `offline_local_only` | T2 cannot be reached; counting, retention and audit continue |
| `refused` | the path is being inspected or an inbound rule was offered; fix before commissioning |

`local_function_affected` is `False` by construction, which is the point of SPEC §3: no cloud failure
degrades local function. Only enrolment genuinely needs the network, so `enrolment_possible` looks at
the enrolment and PKI endpoints alone and reports separately from the general posture.

## Unverified is a refusal

As in F01, three-valued measurement: `None` means nobody probed the endpoint, which is reported as
`unverified` rather than assumed reachable. An endpoint missing from the observation set entirely is
treated the same way.

## Output the engineer hands over

`firewall_sheet()` returns one line per unmet requirement, naming the hostname, its purpose and the
remedy. That is the IT ask left at the site, and it is generated from the same findings the device
acted on, so the sheet cannot disagree with the device's own view.

## Not proven here

Nothing here opens a socket. There is no resolver, no TCP connect, no TLS handshake and no proxy
client — the module scores observations that a probe must produce on the customer's network. The
pinning behaviour is a policy statement until the bridge's TLS stack enforces it against a real
broker, which is phase 7.
