# F01 — Pre-flight host qualification (M01)

**Module:** M01 hardware / SSD platform · **Subsystem:** S01 · **Controls:** C13
**Depends:** none · **Blocks:** F02, F21, T5 onboarding step 7
**Class:** Application (brief + code review; field test required)

## Refusal path

Every outcome is a named `Finding` with a remedy sentence an FE can act on at the counter. There is
no bare fail and no silent pass:

| Finding | Hard | Why |
|---|---|---|
| `arch_unsupported`, `avx2_missing`, `cores_insufficient` | yes | The trunk will not run |
| `ram_insufficient` | yes | Below the D-001 two-adapter floor |
| `nic_missing`, `usb3_missing`, `t1_media_too_small` | yes | The device cannot be deployed here |
| `boot_mode_legacy`, `sleep_enabled` | yes | AD-01 boot chain and unattended operation |
| `host_not_dedicated` | yes | Installed OS booted inside `HOST_DEDICATION_WINDOW_DAYS` (R5) |
| `host_dedication_unverified` | yes | Unmeasured dedication is a refusal, never an assumption |
| `preflight_timeout` | yes | R4: the checker itself missed its 5-minute budget |
| `add_ram_for_third_adapter` | no | Two adapters are offered rather than losing the install |
| `accelerator_absent`, `virtualised_host` | no | Reported; see ADR-REQ-005 |

## Derivation, not assumption

`adapter_cap` comes from measured `MemAvailable` through `canon.ADAPTER_CAP_THRESHOLDS`
(≥3481 MB → 3, ≥3338 MB → 2, below → refuse) by reusing `control.capability.l1_vector`, so the gate
that later enforces the ceiling and the pre-flight that derived it cannot drift apart. `trust_level`
on L1 is `software_bound`; a passing profile can produce the `CapabilityVector` F05 signs, a refused
one produces `None`.

## L1 versus L2/L3

`qualify_host` is L1 only. `qualify_site` is the L2/L3 path (D-007, R6) and is a different type
carrying different fields: no host property can appear in its output and `host_not_dedicated` is
unreachable from it. Calling `qualify_site` with `Profile.L1` raises.

## Read-only by construction

The probe opens no path for writing and never mounts the customer's internal disk. A test asserts
that probing a fixture sysroot leaves every file's mtime unchanged. The one fact F01 R5 needs from
the internal disk — when its OS last booted — is an input to the probe, not something it takes for
itself, and its absence is a refusal (ADR-REQ-006 governs how it may be obtained on the bench).

the portable-media endurance, thermal and power-loss matrix. All are bench and field gates.
