# M08 — Model bundle and the unsealed half

**Module:** M08 inference · **Subsystem:** S03 · **Features:** F08, F09 · **Controls:** C4, C5, C7
**Depends:** M07 (frames), D-010 (unit signing) · **Blocks:** M09
**Class:** Privacy-critical (brief + review + measured age-gate evidence required)

## The model card is part of the contract

F09 R6 makes a documentation gap into a refusal: a bundle whose card does not state the measured
boundary error rate for the 16–24 band cannot be activated, and `model_card_incomplete` names it.
The reason is that an age gate is easy to make look good in aggregate and hard to make good at the
boundary — 99% overall accuracy is compatible with being blind between 16 and 24, which is the only
range the gate exists to judge. The card's `boundary_error_rate["16_24"]` is the only number that
falsifies that, so the release gate demands it and the attestation republishes it.

Activation is a swap. `ModelStore.activate` either installs the candidate or leaves the running
bundle exactly where it was; there is no window in which a device is processing frames with no
active gate because a candidate failed verification. A version floor makes the refusal
`bundle_downgrade` mean what it says: a rollback may restore the previous *release*, and it may not
restore a superseded age gate.

Four refusals, deliberately distinct: `wrong_signing_domain` (signed with the release or policy key
— D-010 gives each unit its own), `signature_invalid` (the bytes do not match, including the card's
bytes, so a "corrected" error rate invalidates the signature), `model_card_incomplete`, and
`bundle_downgrade`.

## A suppression collapse is a compliance event

F09 R4 watches the site's minor-suppression rate against its own baseline, not the fleet's: a
school-adjacent store legitimately suppresses several times what an airport lounge does, so a
fleet-wide expectation would either alert on every honest site or hide a real regression at the busy
ones. A shift beyond two sigma halts the rollout rather than filing a metrics ticket, because the
plausible cause is that the new gate stopped recognising minors.

## The unsealed half is defined by what it cannot accept

`Tracker.update` accepts `BoundaryDetection` and nothing else. There is no constructor in
`t1.analytics.tracking` that takes a `Frame` or a `SealedDetection`, so a track cannot be built from
anything that has not already passed the age gate and the redactor — the age of a tracked person is
not merely unused downstream, it is unavailable. A test asserts this over the module's public
signatures rather than trusting the convention to hold.

Tracks are transient on L1 (SPEC §11). A closed track yields a dwell and a sample count to the
aggregate and is then dropped; `persist` exists so that an attempt to write the trace on a
software-bound device is refused as `c3_forbidden_at_rest` by the trust level, before any
entitlement or schema is consulted (D-008 §1). A single-sample track does not count as a visit,
because one stray detection inflates footfall.

## Not proven here

No model runs. There is no ONNX Runtime session, no NPU delegate, no weights and no measured
accuracy — `ModelStore` gates artifacts it never executes, and the trunk and redactor are still
injected callables. The signing here is HMAC over the bundle's canonical bytes, which proves the
gate's logic and is not the release signature scheme. Association is IoU with a time gap, adequate
to prove the boundary and the transience rules and not yet ByteTrack.
