# M09 — Aggregation, k-anonymity and the Edge Manager loop

**Module:** M09 analytics · **Subsystem:** S03 · **Features:** F11, F19 · **Controls:** C6, C9
**Depends:** M07 (coverage), M08 (tracks) · **Blocks:** M12 egress
**Class:** Privacy-critical (brief + review)

## A suppressed window is not a zero

Below the metric's floor a window emits `k_suppressed`, and the payload carries the flag alongside
the placeholder value. A zero would be indistinguishable from a real zero and would poison every
sum, average and trend computed downstream — the quiet hour would look measured rather than
withheld. The floors come from `canon.CANON_FLOORS`; a signed policy may raise them and cannot lower
them, which `effective_floor` enforces by taking the maximum.

The floors differ by more than a factor of six between footfall (3) and dwell (20) because they
protect different things: counting how many people passed is not the same disclosure as saying how
long each of them stayed, and five visits is ample for the first and nowhere near enough for the
second. Dwell is reported as a median so one loiterer cannot move the number.

Two window-level facts travel with every metric the window emits: `coverage` from M07's cascade and
`time_uncertain` when the clock offset exceeds `CLOCK_SKEW_TOLERANCE_MS` (F14 R6). A window that
counted 40 people at 62% coverage is not a 40, and an analyst must be able to see that without
asking. `time_uncertain` does not suppress the value — the window happened; only its placement in
time is doubtful.

## The Edge Manager cannot write a sentence

    BASELINE -> DETECT -> EXPLAIN -> RECOMMEND -> BRIEF

`Explanation` has no string field. The cause is an enum from a closed set with no `other` member,
and the contributing factors are enums; an explainer that proposes anything outside the set does not
get its output sanitised, it gets `unknown` at reduced confidence. That is both the honest answer
and the reason the field cannot become a channel for "man in a red jacket" — a person description
smuggled through an analytics payload, which is exactly what F19 R2 exists to prevent. One off-set
factor invalidates the whole explanation, because it is evidence the explainer is not constrained
the way the contract assumes.

Recommendations are selected from a signed action library and parameterised from its declared
params; they are never generated locally, and unknown params are dropped rather than passed
through. Each recommendation carries the library version, the expected impact declared by the
signed action, and evidence references.

Caps compose (D-008 §4): each action has a daily cap and the site has three per day. The site cap is
checked last, so a single noisy trigger exhausts its own allowance before it can consume the day's.
A manager who receives fifteen recommendations acts on none of them, which is why the cap is a
refusal rather than a ranking.

`brief` renders with T2 unreachable and marks the briefing `generated_offline` (F19 R3). Nothing in
the loop takes a transport, a network clock or a T2 response.

## Not proven here

There is no baseline learner: `Deviation` is handed an observed value, a baseline and a sigma, and
the code that would compute the last two from 14 days of the site's own history does not exist yet.
No explainer is implemented — `explain` validates an explainer's proposal, which means the local VLM
path (L3) is a contract with nothing behind it. Windows are driven by the caller rather than by a
clock, and no schedule closes them. Outcome measurement, the sixth step of the F19 loop, is not
implemented: recommendations are issued and never yet scored against what happened afterwards.
