# M11 — Local P2P sessions

**Module:** M11 session · **Subsystem:** S05 · **Features:** F18 · **Controls:** C2, C11, C12
**Depends:** M13 audit chain, D-005 · **Blocks:** M17 (every GUI surface sits behind a session)
**Class:** Privacy-critical (brief + review)

## The box verifies, it does not mint

The earlier implementation let the device issue its own session certificates. That reads as a
convenience and is actually the whole vulnerability: a device isolated from T2 could grant itself
whatever it liked, and the 72-hour rule below would become theatre, since the thing being degraded
was also the thing deciding. Certificates are now minted by the T2 session broker, signed in the
`session-cert` domain, and only ever verified here — a device with no path to T2 cannot obtain new
authority, which is the behaviour D-005 actually asks for.

Verification is ordered so that the cheapest lie fails first: domain, then signature, then device,
then validity window. Signing covers every field including `read_only`, so flipping a read-only
certificate to writable invalidates it rather than upgrading it; and binding the domain means a
signature minted for some other purpose in the same key hierarchy cannot be replayed as a session.

`renew` is modelled but not authorised here — the broker's key is not on the box, so what the box
enforces is the *timing* rule (F18: renewal at 75% of TTL, earlier is `renewal_too_early`), which is
what stops renewal from becoming an indefinite extension of one credential.

## Read-only is the state, not the request

`read_only_at` is one predicate consulted at issue, at authorize and at renewal, so there is no path
where a write slips through because a caller forgot to ask. Beyond 72 hours of outage existing
sessions still run to their own TTL — F18 R5 is explicit that they are not cut short — but writes
are refused with `local_session_readonly` and reads continue, which is the difference between a
degraded box and a dead one.

Recovery requires attestation *and* an entitlement refresh. Connectivity is not attestation, and
attestation alone is not entitlement: a device that re-attested but whose entitlements are stale is
still read-only, because the entitlements are what say which purposes it may serve at all.

## A session is a period, so the chain records a period

F18 R3 wants user, purpose and duration, and duration only exists at the close. `open` and `close`
are therefore separate records, and `expire_due` closes an abandoned session at its own expiry
rather than at the sweep time — otherwise the recorded duration would be an artefact of when the
sweep happened to run. The same certificate cannot open a second concurrent session, so one issued
credential is one auditable presence on the box.

Live answers are labelled `live_onsite` and carry C2, which is what bounds keeping them (F18 R4).
The label is on the response object rather than left to the caller, so a live figure cannot be
quietly retained as if it were an aggregate.

## Not proven here

There is no server. F18 R1 wants the cloud OpenAPI paths served over mTLS on the LAN with client
certificates validated against the Session CA; what exists is the authorisation core those handlers
would call, so no port is bound, no TLS handshake happens, and no client certificate chain is
verified — the HMAC signature stands in for the CA's X.509 signature, and the mTLS layer that F18
R1 actually specifies is absent. "Given an L1, when scanned, then no P2P port is open" is a scan
result: `listening` is a property here, and no L1 build has been scanned.

There is no T2 session broker, so the issue and renewal paths are exercised against a test key
rather than against real T2 issuance, and nothing has proven that the broker refuses to mint what
the box refuses to accept. Retention of live responses is a label, not an enforced deletion: the
class is carried, but nothing yet holds these responses or deletes them, since no handler stores
them. Attestation and entitlement refresh are booleans set by a caller — the real attestation
exchange belongs to M15 and T2 and does not exist.
