# M07 — Decode admission and cascade orchestration

**Module:** M07 ingestion · **Subsystem:** S03 · **Features:** F07 · **Controls:** C4, C11
**Depends:** M01 (profile and stream cap), M08 (sealed pipeline) · **Blocks:** M09
**Class:** Privacy-critical (brief + review + bench measurement required)

## The load decision is taken where no pixel exists

F07 R4 permits overload to degrade the *sample rate* and forbids it to degrade *privacy*. That is
one sentence with a structural consequence: the cascade may never be in a position where it has
already decoded a frame and must choose which stage to skip. So `admit` and `offer` are separate
calls, every drop is decided in `offer` before the frame is handed over, and once
`SealedPipeline.process` is entered the frame goes through motion, trunk, age gate and redaction
without exception. There is no code path that produces an output having skipped one of them.

Dropping frames is honest only if it is visible. `data_quality()` reports processed/offered as
`coverage`, and M09 attaches it to every metric the affected windows emit, so a busy Saturday shows
up as a coverage note rather than as a quiet undercount that reads like a bad trading day.

## Two caps that look alike and are not

`stream_cap` comes from the signed host profile and is checked at admission — before a decoder is
started, because the reason for the cap is RAM the decoder would consume. `budget_fps` is a
measurement of what this host can carry through the full sealed path and is checked per frame. A
host that exceeds its stream cap is misconfigured; a host that exceeds its frame budget is merely
busy, and the two are reported differently: `stream_cap_exceeded` is a refusal with a remedy,
overload is a drop with a coverage cost.

L1 decodes keyframes only (D-001). That is a property of the profile, not a tuning knob, so it lives
in `KEYFRAME_ONLY` next to the cap rather than in configuration.

## A dead sealed process stops the stream

`SealedPipelineDown` un-admits the stream and returns `sealed_pipeline_down`. The next frame on that
stream is then refused as un-admitted, so the stream stays stopped until the sealed unit is
restarted and commissioning re-admits it. This is the fail-closed path F07 R5 requires: no unsealed
fallback exists to fall back to, and the refusal says so.

## Stage gating

| Stage | Runs on |
|---|---|
| S0 motion | every offered frame that survived admission |
| S1 trunk | frames with motion (a quiet stream does not re-run the trunk) |
| age gate, redact | every frame the trunk saw |
| S2 tracking | post-gate, post-redaction detections only |
| S3 resolve | detections S2 left below `S3_CONFIDENCE_CEILING` |

S2 and S3 are selector methods rather than pipeline steps because they run outside the sealed
process, in M08's unsealed half; the cascade decides what they are allowed to see, not what they do.

## Not proven here

Nothing here decodes. There is no demuxer, no keyframe parser, no hardware decode session and no
scheduler thread — the module decides what a decoder must do and counts what it did. `budget_fps` is
supplied, not measured: the measurement needs a real stream on real silicon, and until that bench
run exists the overload behaviour is correct policy against an assumed number.
